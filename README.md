# Svaston VPN Aggregator

Автоматический сборщик VPN-конфигов из **публичного** Telegram-канала → нормализация → пуш в GitHub.
**Без api_id / api_hash, без входа, без бота** — только @username канала.

**Как работает:**
1. По расписанию (или вручную) скрипт читает последние сообщения канала через публичную страницу `t.me/s/<имя>`.
2. Достаёт **прямые ноды** (`vless://`, `vmess://`, `trojan://`, `ss://`, `ssr://`, `hysteria2://`, `tuic://`, `shadowtls://`, `wireguard://`, `ssh://`) **и ссылки на подписки** (`https://…/sub?token=…`).
3. Для ссылок на подписки делает fetch (несколько User-Agent, decode base64/gzip) и распаковывает в ноды.
4. **Мерджит** новые ноды с тем, что уже в репо (набор накапливается, не теряется), дедуплицирует.
5. Генерирует артефакты и пушит в `out/` репо одним коммитом через GitHub Git API.

```
t.me/s/<канал> ──> tmscraper (веб-превью, ~20 msg/страница, назад по id)
                            │
        extract URIs + sub-URLs ──(fetch + base64 decode)──> ноды
                            │
                normalize + dedupe + накопление (nodes.json)
                            │
        nodes.json  sub/b64.txt  nodes/*.txt  sing-box  clash
                            │
                 push -> GitHub repo /out
```

## Что попадает в репо (`out/`)
| Файл | Для чего |
|---|---|
| `out/nodes.json` | Канонический список всех нод (источник правды, основа дедупа) |
| `out/sub/b64.txt` | **Сводная base64-подписка** — импорт в 1 клик в v2rayN / sing-box / Streisand |
| `out/sub/combined.txt` | Тот же список, plain-text (одна URI на строку) |
| `out/nodes/<имя>.txt` | Файл на каждую ноду (сырой URI) |
| `out/singbox/config.json` | Готовый sing-box конфиг (best-effort) |
| `out/clash/config.yaml` | Готовый clash-конфиг с прокси-группами (best-effort) |
| `out/meta.json` | Дата, счётчики по протоколам, состояние сканирования, предупреждения |

**URL для импорта** (после первого пуша, `OWNER`/`REPO` — твой репо, `main` — твоя ветка):
```
https://raw.githubusercontent.com/OWNER/REPO/main/out/sub/b64.txt          # base64-подписка
https://raw.githubusercontent.com/OWNER/REPO/main/out/sub/combined.txt     # plain-text
https://raw.githubusercontent.com/OWNER/REPO/main/out/singbox/config.json  # sing-box
https://raw.githubusercontent.com/OWNER/REPO/main/out/clash/config.yaml    # clash
```

## Настройка (2 шага)

### Шаг 1. Узнай @username канала
У публичного канала есть username: ссылка `t.me/<имя>`. Взял `имя` — это и есть канал.
(Приватные каналы без username так **не читаются** — для них нужен вход через аккаунт, см. «Приватные каналы» ниже.)

### Шаг 2. Секреты в GitHub
В репо: **Settings → Secrets and variables → Actions → New repository secret**:
| Секрет | Что |
|---|---|
| `TG_CHANNEL` | `@username` или `username` публичного канала |
| `GH_TOKEN` *(опц.)* | PAT, **если** пушим в **другой** data-репо |
| `GH_REPO` *(опц.)* | `owner/data-repo`, если пушим в другой репо |

Готово. Workflow `refresh-sub` запускается по расписанию (каждые 15 мин). Первый коммит в `out/` появится после первого успешного запуска.

> По умолчанию пуш в тот же репо (дефолтная ветка). Чтобы держать данные в отдельном публичном data-репо — задай `GH_TOKEN` (PAT с write) и `GH_REPO=owner/data-repo`.

## Ручные прогоны
```bash
pip install -r requirements.txt

# Локально, без пуша: читает канал и пишет в ./out
python main.py --channel @username --lookback 300

# Офлайн: собрать артефакты из готового nodes.json (без сети)
python main.py --nodes-file tests/out/nodes.json
```

## Тесты (без сети, без Telegram)
```bash
python tests/selftest.py
```
Проверяет разбор всех протоколов, распаковку base64-подписки, дедуп и генерацию артефактов.

## Конфигурация
- **Расписание** — `.github/workflows/refresh.yml` → `on.schedule.cron` (сейчас `*/15 * * * *`).
- **Глубина сканирования** — `TG_LOOKBACK` / input `lookback`. Влияет в основном на первый запуск (бэкфилл); дальше бот читает только новое.
- **Лимит подписок** — `SUB_FETCH_MAX`.
- **Формат вывода** — включено всё; что-то отключить/дописать можно в `aggregator.build()`.

## Как накапливаются ноды
Каждый запуск берёт текущий `out/nodes.json` + новые ноды из прочитанных сообщений, мерджит по ключу
`(protocol, host, port, credentials, network/path/sni)` и пишет обратно. Поэтому:
- ноды не пропадают, даже когда пост уходит далеко назад;
- повторная отправка той же ноды не создаёт дубли;
- состояние сканирования (`oldest_id` в `meta.json`) экономит запросы: при тихом канале за запуск идёт 1 запрос к t.me/s/.

> **Удалить ноду** — нужно убрать её из `out/nodes.json` (редактируй файл в репо). Можно добавить чёрный список по домену, если нужно.

## Частые проблемы
- **`Не удалось прочитать <канал>`** — канал приватный или username неверный. Проверь, что канал публичный (`t.me/<имя>` открывается в браузере без входа).
- **Подписка отдаёт 401/403 или пустоту** — сервер требует конкретный User-Agent. Список в `subfetch._HEADS`, можно добавить свой.
- **Captcha / 429 от t.me/s** при очень частом опросе — урежь частоту (cron реже) и/или `lookback`.
- **Нет clash** в `out/` — нужен `PyYAML` (в `requirements.txt` уже есть).
- **Много предупреждений в `out/meta.json`** — ноды, которые не удалось перевести в sing-box/clash (обычно ssr/wireguard). Сам raw-URI при этом **всегда** в `sub/` и `nodes/`.
- **Rate limit GitHub** при большом числе нод — guard пропускает пуш, если набор не изменился.

## Приватные каналы (опционально, если публичного подхода мало)
Если канал приватный или хочется читать весь архив — можно вернуться к MTProto через аккаунт: `login_headless.py` (разовый вход) + секреты `TG_API_ID`/`TG_API_HASH`/`TG_SESSION`. Методика описана в git-истории / `login_headless.py`. Для большинства «каналов-выкормщиков» публичного доступа хватает.

## Юридические/этические заметки
- Собирай только то, к чему у тебя есть легитимный доступ (публичные данные).
- Подписки в каналах могут нарушать ToS провайдеров или авторское право — используй на свой риск.
- Инструмент для личного/семейного использования. Не публикуй собранные ключи/токены широко.
